# Project phases, status, and what remains

(updated 2026-10-29)

## The original purpose

Show that **AI-assisted procedural audio** is a viable, MIT-licensed alternative to
text-to-audio models released under non-commercial licenses: an AI agent researches a sound and
writes code that synthesizes it, and no AI runs at sound-generation time.

## Phase 1: AI-written procedural generators (2026-02, opencode + GLM-4.7)

**Built:** ten Python/numpy generators (thud, button click, explosion, flying saucer, gravel
footsteps with 3D panning, four siren variants, wind), an interactive human-in-the-loop trainer
(`sfx_trainer.py`), a demo page, and a first stick-slip hinge generator.

**How it fits now:** the baseline. It proved simple sounds (impacts, clicks, sweeps, sirens)
work well with hand-built synthesis. It also showed where that approach stops: the door creak
"sounded like wind" and the first hinge generator didn't sound like a hinge.

**Remaining (original purpose):**
- [ ] **Reproducibility:** none of the 8 generators that use randomness seed it, so "same inputs
  = same outputs" isn't true for Phase 1 yet. Add a `seed` parameter (as Hinge Lab does).
- [ ] **Sirens:** the US wail is too low; it needs more harmonic content and better tremolo.
  "Siren (Realistic)" (`siren_realistic_generator.py`) was removed from the demo page in
  2026-10 because it doesn't sound realistic. Restore it after a research-backed rework.
- [x] **Thud** revised 2026-10: the original was ~97% below 100 Hz and inaudible on laptop/phone
  speakers. It now has a click, a 200→80 Hz pitch-drop body, and a 200–600 Hz knock, and is seeded.
- [ ] **More sounds** from the original plan: rain, thunder, fire, water, birdsong.
- [ ] **Techniques:** proper IIR/FIR filters, reverb, granular/wavetable synthesis, HRTF.
- [ ] **Batch generation** for game-audio asset pipelines.
- [ ] **AGENTS.md** still describes Phase 1 only. Add Phase 2 tools (Hinge Lab, analysis, site).
- [ ] `sfx_trainer.py` still uses the Phase 1 hinge generator.

## Phase 2: research-driven squeaky hinge (2026-10, Claude Code + Claude Opus 5.5)

**Built:**
1. **Research briefing** ([domain-expertise.md](domain-expertise.md)): friction acoustics,
   stick-slip, mode lock-in, elasto-plastic friction equations, sourced from primary papers.
2. **Hinge Lab** (Rust, egui): physical friction model with sliders, CLI, seeded
   bit-identical renders, WAV + JSON sidecars, background screenshot mode.
3. **Reference analysis** (`tools/squeak_analysis.py`): event detection, pitch/roughness tracking
   with octave correction, segmentation at pitch jumps, five-category taxonomy, slip-pulse
   resynthesis, HTML report, and a publish mode with no reference audio.
4. **Demo site** (`tools/build_site.sh`): Phase 1 page with regenerated sounds, Phase 2 page,
   publish-mode analysis.

**Key finding:** the physical model is right about *when* a hinge squeaks but wrong about *what it
sounds like*. Real squeaks are sequences of parts (pitch plateaus with jumps, glides,
smooth/rough alternation) with bright pulse-driven spectra. A segment-based resynthesis from
measured contours reproduces these.

**How it fits:** Phase 2 delivers the original thesis for a harder sound, and adds two
capabilities Phase 1 lacked: **grounding in measurements of real sounds**, and **reproducible,
parameterized output** that a UI (and later an LLM) can drive.

**Remaining (new capabilities):**
- [ ] **Segment-score synth in Hinge Lab:** each squeak as a list of parts (type, duration,
  start/end pitch, curve, roughness, brightness, click rate), driven by sharp slip pulses through
  hinge and panel resonances. "Load from analysis" imports any analyzed event.
- [ ] **Parameter fitting:** search score parameters (e.g., CMA-ES) to match an analyzed event,
  then report the remaining error per feature.
- [ ] **Text → sound:** an LLM writes a segment score (JSON, validated against a schema) from a
  description; then evaluate with listening tests (see domain-expertise.md §8).
- [ ] **Analysis quality:** verify the ~octave jumps in events #16, #18, #20; improve creak-pulse
  detection (gaps in #6); make creak pulse levels less uniform.
- [ ] **Other friction sounds** with the same exciter: chalk, sneaker squeak, wineglass, brake
  squeal, creaking floorboard.
- [ ] **Own reference recordings** (self-recorded or CC0) so reference audio can be published
  alongside the analysis.
- [ ] **Listening tests:** blind A/B of Phase 1 vs. Hinge Lab vs. segment resynthesis.

## Provenance rules

- Everything generated by this repo's code is MIT.
- Third-party reference recordings live only in `references/` (gitignored) and are never
  published. Published analysis shows derived spectrograms and measurements and links to the
  source with timestamps.
- Resyntheses are generated by our code, but they follow the measured pitch, timing and spectral
  envelope of each reference event. They are published as our output; revisit this if the source
  owner objects.
